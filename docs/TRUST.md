# Trust, verification and privacy

Trust is central to the concept.

## Information sources

The prototype is designed around:

1. Community-submitted information.
2. Information reviewed by designated community representatives.
3. Relevant public civic information.
4. Structured feedback from residents.

## Verification

Community information should not automatically become a community rule. The interface should distinguish:

- **Verified by community** — reviewed by an appropriate local representative.
- **Under review** — submitted but not yet validated.
- **Resident perspective** — an individual's experience or interpretation.
- **General guidance** — broadly applicable advice rather than a local rule.

## AI boundaries

The system should not:

- invent cultural rules;
- make broad claims about ethnic or religious groups;
- determine who is right in a dispute;
- expose private reports;
- present generated text as verified local fact.

## Privacy

Conflict reports should minimise personally identifying information. Where possible, community leaders should see patterns and themes rather than unnecessary personal details.

Sensitive information should only be collected when necessary for a clearly defined user need.
